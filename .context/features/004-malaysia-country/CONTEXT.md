# Feature: Malaysia Country Expansion

**Base:** 168810eeb12c6e9d5bd257c0b0df9620315d765e

## Goal

Add Malaysia (`MY`) as a third, fully independent country in the market intelligence pipeline, using the real source list Alfonso received from the Malaysia branch (`Source_submission_Malaysia.xlsx`, submitted by Suex Ching) — reusing the country-scoping infrastructure Vietnam already made generic, and preserving Malaysia's full real business-domain breadth in the data even though only BER/EDU/GENERAL become active pipeline domains this round.

## Scope

**In scope:**
- New `"Malaysia"` / `"MY"` country block in `config/sources.json`: 55 sources (the submission's header claims 61, but rows 56-61 are blank — 55 is the real, recounted total) mapped into the existing 6-sector taxonomy (mapping is 1:1 and unambiguous — see Decisions), with MY's own `priority_keywords`/`keywords` lists.
- Every MY source keeps its real submitted business domain (`BER`/`RCC`/`HLS`/`MFG`/`CTE`/`PSS`/`EDU`) as a tag in its `domain` array, alongside `"GENERAL"` so it's reachable in the currently-active domain views — see the Domain Scope Decision below. This is what makes the full source list actually usable today without waiting on full domain-taxonomy activation.
- Flip Malaysia from an inert `<span>` to a real link in `templates/base.html`'s country-tabs block, mirroring Vietnam's Task 004. Indonesia stays inert (still no data).
- Add a parallel Malaysia subsection to `data/company_context.md`'s "Key Prospects & Relationships" and "Ecosystem Players" sections (covering the full real business breadth of the source list, not artificially restricted to BER/EDU, for the same forward-compatibility reason as the domain tagging), then re-seed `COMPANY_CONTEXT`.
- Scraper dry-run verification of all 55 URL-bearing MY sources (fetcher tiering + `active`/`inactive_reason`), mirroring Vietnam's Task 002.

**Explicitly NOT in scope (this is the one point that needed Alfonso's explicit call — see Decisions):**
- Activating RCC/HLS/MFG/CTE/PSS as real, first-class pipeline domains (`_domain_mode()`'s validated set, dedicated domain tabs/checkboxes, and — most importantly — `pipeline/analyst.py`'s `SUMMARY_PROMPT` product catalog and opportunities-gate keywords, which are currently BER/EDU-only). This is a materially larger feature that affects Singapore and Vietnam too, not just Malaysia, since `domain` is orthogonal to `country`. Company_context.md's RCC/HLS/MFG/CTE/PSS product-catalog content already exists (written during Feature 001, marked "reference only, not active this round") — the gap is entirely in routing/prompt wiring, not missing content. **This is a known, explicitly deferred next step, not a forgotten one** — flagged here, and to be flagged again in `.context/STATE.md` and `.context/DECISIONS.md` once this feature passes review, exactly per Alfonso's request.
- Any change to the analysis architecture, opportunity scoring rubric, or RAG mechanism.
- `app.py`, `main.py`, admin.html, or feedback/weekly-summary country-scoping code — **all of this is already fully generic from the Vietnam feature and needs zero changes for Malaysia.** This is the one significant way Malaysia's scope is smaller than Vietnam's.
- A live `main.py --country=MY --domain=BER` (or `--domain=GENERAL`) end-to-end run burning Groq quota — stays an Alfonso-owned manual checkpoint, same as SG's and VN's still-open checkpoints.

## Implementation Decisions

- **Domain scope for this round — Malaysia (and, going forward, Vietnam) stays scoped to BER/EDU/GENERAL, matching the existing active pipeline domains, NOT full 7-domain activation.** *(User decision — the one genuinely blocking call in this feature.)* Rationale given: full 7-domain activation is materially bigger than "add Malaysia" (it changes routing/UI/prompt behavior for all countries, not just MY), so it's being deliberately deferred as its own future feature rather than folded in here. Explicit instruction from Alfonso: this must not get lost — record it clearly in this CONTEXT.md (done) and again in `.context/STATE.md`/`.context/DECISIONS.md` once this feature passes `/feature-verify`, as the clearly-flagged next step after any fixes from this round's dashboard review.
- **Every MY source is tagged with BOTH `"GENERAL"` and its real submitted business domain** (e.g. `["GENERAL", "RCC"]`, `["GENERAL", "HLS"]`, not just `["GENERAL", "BER"]` for everything). *(Claude's default judgment, directly implementing the "preserve the full source list for future domain expansion" requirement Alfonso stated when making the domain-scope call above.)* Rationale: since `main.py`'s domain filter checks `domain_arg in source["domain"]`, every source is reachable today via `--domain=GENERAL` regardless of its real domain, while the real tag sits ready for the deferred domain-activation feature to pick up later with zero data migration needed.
- **Sector mapping** — Malaysia's `Relationship Type` column maps 1:1 onto the pipeline's existing 6 sectors, no ambiguity (unlike Vietnam's ad hoc categories): `Customer` → `customers` (26), `Partner` → `partners` (10), `Government` → `gov_agencies` (7), `Association` → `associations` (3), `Competitor` → `competitors` (8), `General News` → `general_news` (1). *(User-confirmed by inclusion in the source list itself — the column values already match the taxonomy's own vocabulary.)* Note: this is the first source list to populate the `associations` sector with real non-SG entries (GreenRE, REDHA Institute, Malaysia Retail Chain Association) — `associations` already exists and is exercised for SG (SGBC/REDAS/etc.), so this isn't a new sector, just the first time VN's gap in that sector doesn't repeat for MY.
- **Source count: 55, not the header's stated 61.** *(Claude's default judgment, mirroring the same recount discipline Vietnam's Task 001 required.)* Rows 56-61 in the submission are blank despite the header field.
- **No missing-URL entries this round** — every one of the 55 populated rows has a URL. *(Fact, not a decision — simpler than Vietnam, which had 8 no-URL stubs.)*
- **No EDU dual-tagging needed** — unlike Vietnam's MOET/Văn Lang University/HUIT pattern, none of Malaysia's EDU-tagged sources (Inkube Edu, U Learning, Unbound Malaysia) show a clear BER overlap in their descriptions. *(Claude's default judgment — flag to Alfonso if he disagrees on any specific source during review.)*
- **MY's own `priority_keywords`/`keywords` are NOT a simple copy of SG's/VN's BER-centric list.** *(Claude's default judgment.)* Rationale: only 17/55 (31%) of MY's sources are BER-tagged; the rest span RCC (13), PSS (13), HLS (4), CTE (3), MFG (2), EDU (3). Reusing a pure-BER keyword list as-is would filter out the large majority of MY's real source list at the relevance-filter stage even though those sources are domain-tagged and reachable — defeating the "use the full source list" goal within this round's own scope. MY's keyword lists include the existing BER/XR/digital-twin terms (for BER/EDU/GENERAL relevance) plus a modest, representative set of cross-sector terms drawn directly from the submission's own Description column (retail/showroom/virtual tour terms for RCC, healthcare/hospital/safety-training terms for HLS, factory/manufacturing terms for MFG, tourism/heritage/event terms for CTE, government/smart-city/grant terms for PSS) — this is NOT the same as building the full domain-activation feature (no routing/UI/prompt changes), it only affects whether these sources can pass the keyword-relevance filter at all. **Important, explicitly accepted limitation:** even sources that pass this broadened filter will generally NOT generate `opportunities` entries in the report, because `SUMMARY_PROMPT`'s opportunities gate is still BER/EDU-keyword-only per the domain-scope decision above — broadened filtering surfaces these sources' raw signals, but the "opportunities" section stays BER/EDU-flavored until the deferred domain-activation feature lands. This asymmetry (signals visible, opportunities gated) must be visible to Alfonso during dashboard review, not silently absorbed.
- **company_context.md's Malaysia subsection covers the full real business breadth** (not restricted to BER/EDU), for the same forward-compatibility reason as the domain-tagging decision above — mirrors Vietnam's Task 007 pattern but pulls from all of MY's real categories, not just BER-flavored ones.
- **Branching:** this feature branches from `main` (168810e), independently of `feature/003-vietnam-country` (still unmerged, under Alfonso's review). *(Claude's default judgment, mirroring the VN-vs-LLM-backend precedent.)* **Known, low-risk consequence:** since both VN's and MY's branches touch `templates/base.html`'s country-tabs block, and MY's branch is based on a pre-VN-fix `main`, MY's own base.html task must independently re-produce the "Vietnam is a real link" state (not just add Malaysia) so this branch is internally correct on its own. When VN and MY eventually both merge to `main`, expect a small, easily-resolved textual merge conflict on that block (both branches converge on the same final content — SG/VN/MY as real links, ID inert — so resolution is trivial, not a real design conflict).
